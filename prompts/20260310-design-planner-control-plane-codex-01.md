# Design Planner Control Plane Prompt

Use when:

- designing the planner control plane as a terminal-first platform feature
- defining canonical planner artifacts, graph semantics, and contract projections
- drafting architecture and spec documents before implementation

Operating stance:

- default to direct, adversarial critique of weak assumptions
- reject hidden state, UI-first design, and external-system authority
- prefer explicit local artifacts, schemas, and command contracts

Required outputs:

- architecture decisions with rationale
- explicit schema or contract proposals
- identified open questions with recommended disposition
- concise summary of unresolved risks
