# Platform Game

## Objective

The platform game is the top-level game. Its objective is to build and operate an AI-native development and project-management platform whose local state, decisions, validations, and merges are auditable and Codex-orchestrable.

## Players

- human authority
- Codex orchestrator
- validators as referees

## Layer

The platform game is the root layer. It owns the shared board and the
inherited board law that every lower game must obey.

## Board

The platform board is the union of:

- repository state
- canonical graphs
- ExecPlans
- governed specs
- research provenance artifacts

## Inherited Board Law

- forbidden moves
- scope compliance
- no hidden state
- canonical state ownership
- determinism
- human authority boundaries

## Referee Order

1. global board law
2. active domain game
3. active subgame

## Win Condition

The platform game succeeds when lower-level games can be played coherently without hidden state or governance drift.

## Loss Condition

The platform game fails when subgames conflict, canonical sources of truth become ambiguous, or validators no longer align with documented rules.
