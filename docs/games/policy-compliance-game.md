# Policy-Compliance Game

## Objective

The policy-compliance game proves that a governed slice is being played legally before hostile review or human review begins.

## Layer

The policy-compliance game is an assurance-layer game attached to implementation work. It inherits global board law, then enforces policy rules that are narrower than platform law but broader than a single proof obligation.

## Board

The policy-compliance board emphasizes:

- current implementation branch state
- canonical remaining-work graph state
- queued backlog mirror state
- commit stack structure
- merge-readiness prerequisites

## Legal Moves

- inspect
- reconcile
- validate
- block
- recover

## Local Rule Focus

- procedural commit order
- human-sized commits
- latest-main branch alignment
- clean merge state
- graph-action-required
- stale-queue blocking

## Win Condition

The policy-compliance game succeeds when the branch can prove that advancement depends on passing referee evidence rather than agent assertion.

## Child Subgame

The policy-compliance game contains the commit-structure subgame, which narrows local legality to the reviewability and sequencing of the commit stack.
